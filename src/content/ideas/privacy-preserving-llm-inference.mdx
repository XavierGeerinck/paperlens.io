# The Confidentiality Crisis

As Large Language Models (LLMs) become integral to enterprise and personal workflows, a critical bottleneck remains: **privacy**. Sending sensitive financial data, medical records, or proprietary code to a third-party cloud provider requires a level of trust effectively equivalent to "full exposure."

The "Operational Notion of Privacy" defines a gold standard: **only the client can read the prompt and the corresponding completion, end-to-end.**

A recent survey from IACR (2026/105) outlines a "trust-minimizing trajectory" for achieving this, spanning from today's hardware-based solutions to a future of purely mathematical guarantees.

## The Deployment Trajectory

The landscape of privacy-preserving inference (PPI) is not monolithic. It represents a trade-off space between performance, cost, and trust assumptions.

### 1. Trusted Execution Environments (TEEs)
Currently the most practical solution for high-performance confidential computing. TEEs like **Intel TDX** or **NVIDIA H100 Confidential Computing** create a secure "enclave" within the processor.
- **Mechanism**: Data is encrypted in RAM and only decrypted inside the CPU package.
- **Trust**: You must trust the hardware manufacturer (e.g., Intel, Nvidia) and the cloud provider's physical security (to some extent).
- **Performance**: Near-native speed (~10-20% overhead).

### 2. Multi-Party Computation (MPC)
MPC splits the trust across multiple non-colluding servers.
- **Mechanism**: The model weights and user inputs are split into "secret shares." Server A and Server B compute on their shares without ever seeking the full data.
- **Trust**: Assumes the servers do not collude to reconstruct the data.
- **Performance**: High communication overhead; significant slowdown compared to plain inference.

### 3. Fully Homomorphic Encryption (FHE)
The holy grail of cryptography.
- **Mechanism**: Computations are performed directly on encrypted data. The server receives ciphertexts, processes them, and returns a ciphertext result. The server *never* sees the keys.
- **Trust**: Purely mathematical (Lattice-based cryptography).
- **Performance**: Currently orders of magnitude slower (1,000x - 1,000,000x), though hardware acceleration is improving this rapidly.

## Core Concept: Additive Secret Sharing

To understand how MPC reduces trust, we can look at its simplest primitive: **Additive Secret Sharing**. This allows two servers to compute $y = Ax$ (matrix multiplication, the core of LLMs) without either server knowing $x$.

## The Path Forward

The researchers propose a phased adoption:
1.  **Immediate**: TEEs for general-purpose, low-latency confidential LLMs.
2.  **Mid-term**: Crypto-augmented designs (TEEs + lightweight MPC) to distribute trust.
3.  **Long-term**: FHE or FHE-hybrid schemes as specialized accelerators (ASICs) become available to handle the massive computational overhead of lattice cryptography.

This trajectory allows organizations to adopt confidentiality *now* while preparing for a "trustless" future.
